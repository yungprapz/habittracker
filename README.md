# Bloom
A mobile-first, dependency-free habit PWA. Node 24 runs tests; Python 3 serves the app. No build step or account required.

## Develop
Run `npm start` from this directory (port 3000). Run `TZ=America/Toronto npm test` for schedule, history, persistence, leap-year, DST, never-miss-twice streak, weekly habit, flower, milestone, automaticity and calendar reminder tests.

## Host and install
Upload index.html, app.js, model.js, garden.js, garden-ui.js, reminders.js, bloom-reminders.ics, style.css, sw.js, manifest.webmanifest and both PNG icons to a static HTTPS host (for example GitHub Pages). Relative URLs support subdirectories. Serve the manifest with a JSON/manifest MIME type and sw.js as JavaScript without long-lived HTTP caching. Increment the service worker CACHE version whenever shell files change. The service worker checks every file with the server before using it, so a new deploy shows the next time the app is opened even though GitHub Pages lets browsers reuse files for 10 minutes. Each fresh copy also replaces the offline one. Open the hosted URL in Safari, Share → Add to Home Screen → Add. Open once online before offline use. No Xcode or Apple Developer membership needed. It is deployed at https://yungprapz.github.io/habittracker/ by GitHub Pages from `main`.

## Data
LocalStorage stores checkoffs and dated routine versions. Edits apply today onward; older routines retain their original names, schedules and order. Tracking begins on first use. Export/restore JSON backups from Your Routines. Browser data deletion removes local records; there is no cloud sync. Streaks follow a "never miss twice" rule: one missed day pauses a streak (it isn't counted, but the streak survives), two missed days in a row reset it, and an unfinished current day never counts as a miss. Each routine can have an "After I…" anchor that appears on its card. A habit can be set to "Any N days a week" (retinol defaults to any 2): it appears every day, a day without it never counts as missed, and progress is counted Monday to Sunday. Habits on light tracking stay checkable but are left out of daily totals, calendar completion and flower requirements. Older saves and backups are upgraded automatically. Archived habits retain past records. Calendar dots mark hair-oiling completion. A day runs until 4:00 am by default (Routines → Evening routine → Evening day ends at, midnight to 6:00 am), so checkoffs made after midnight count for the evening before. Streaks, flowers and the calendar all use that day.

## Reminders
Times default to 07:00 and 22:00 local time. Routines → Reminders → **Add reminders to my calendar** adds a repeating daily calendar event for each routine, with an alert at its time (on iPhone, tap Add All). iOS blocks `data:` and `blob:` calendar files in Home Screen apps, so the button links to a real `.ics` URL. Default times use the static `bloom-reminders.ics`, which the host serves as `text/calendar`; other times are generated by the service worker from `bloom-reminders.ics?m=HH:MM&n=HH:MM`. Both come from reminders.js, and a test checks the static file still matches it. Events use floating local times, so alerts follow the phone's time zone. Changing a time means deleting the old events and adding them again; the app says when. Calendar reminders have not been tested on a physical iPhone yet. Apple Reminders steps remain in the app as a fallback.

For actual Web Push on iPhone, iOS 16.4+ requires installation on the Home Screen and permission requested from a user gesture. A future deployment needs a VAPID key pair, subscription API with validation, persistent subscription storage, unsubscribe/delete support, and a scheduled server job. Store an IANA timezone and both local reminder times per subscription; handle DST, deduplicate each local date/routine, and remove expired subscriptions on 404/410. Send encrypted Web Push and handle push/notificationclick events in the worker. Keep VAPID private keys on the server. Do not use browser timers for background delivery. This static version has no subscription endpoint, push sender, or scheduler, so push is not enabled or tested. No hosting credentials are configured here.

## Flower studio and demo
Open `/?demo` on the running server for isolated sample progress (21 hair-oiling days, a finished bouquet, and an unlocked scratch reward). It uses a separate `bloom-demo` storage key; exit demo returns to real data. No demo progress is stored in the normal profile.

Complete the scheduled morning routine to collect a Cosmos, Anemone or Daisy, and the evening routine to collect a Moonflower, Evening primrose or Night phlox: up to two stems per local day. On Today, a finished routine folds into a short card holding that routine’s flower choice, and unfinished routines come first. To collect for an earlier day, tap it in Today's week strip. About one stem in ten blooms rare (golden-edged), without warning. A stem collected the day after a missed routine is always rare, as a welcome-back. Seven stems form a bouquet. The Flowers tab shows the bouquet in progress, the shelf of finished bouquets, earned treats and a single "next treat" row. Today stays checklist-first: a slim progress header, the week strip, the routines, and one hair-oiling line whose streak rule sits behind a "?". Progress shows the calendar and a one-line summary of the chosen day that opens for corrections. Routines groups habits under their routine, with its "After I…" cue and time in the header. Navigation is a floating pill bar: Today, Flowers, Progress, Routines. Daily requirements are captured when evaluated. Correcting a qualifying checkoff reconciles that day's stem. Missed future days do not remove collected stems.

Hair-oiling milestones at 21, 42 and 66 streak days ("fully bloomed") unlock a reward once each. Reveals use a local curated surprise pool, not an AI service or live shopping search. Scratch with a pointer or use the accessible Reveal reward button. Treats are free. Claimed rewards remain recorded. No purchases or notifications are sent.

## Why it works this way
- **Never miss twice.** A single missed day doesn't measurably slow habit formation (Lally et al. 2010), but a broken streak demotivates more than the lapse warrants (Silverman & Barasch 2023).
- **Welcome-back rare bloom.** In Milkman et al.'s 2021 megastudy, a small bonus for returning after a missed workout was the best of 54 interventions.
- **Flower choice right after a routine.** Rewards strengthen habits most when they follow the behaviour immediately (Wood & Rünger 2016).
- **"After I…" anchors.** Habits form through repetition in a stable context, and if-then plans help (Gollwitzer & Sheeran 2006; Sheeran et al. 2024). Most habit apps rely on time reminders only (Stawarz et al. 2015).
- **66-day milestone.** The median daily habit takes about 66 days to feel automatic, ranging from 18 to 254 days (Lally 2010; Singh et al. 2024).
- **Unannounced rare blooms.** Expected tangible rewards can undermine intrinsic motivation; unexpected ones don't (Deci, Koestner & Ryan 1999).

Current illustrations are lightweight original SVG artwork rather than the detailed mockup illustration assets. Physical iPhone Safari testing and HTTPS deployment remain outstanding. Browser screenshots in demo/ show the actual implementation.
