# Bloom handoff

Read README.md first. This is a dependency-free, mobile-first PWA for skincare, hair care, and supplement habits. It runs directly as static ES modules; Node 24 runs the tests, Python 3 serves the app. Use the existing checkout. No worktree is necessary unless requested.

## Run
- `npm start` (port 3000)
- `npm test`
- Open `http://localhost:3000/?demo` in the browser on the machine running the server. Cloud deployments require a forwarded preview or HTTPS hosting; localhost on someone else's device will not reach this server.
- Demo uses separate localStorage (`bloom-demo`) from real data (`bloom-v1`).
- After changing reminders.js, regenerate the default calendar file (keep this start date; a test compares against it): `osascript -l JavaScript -e "$(cat reminders.js); encodeURIComponent(bloomReminders.ics({},{start:new Date(2026,10,17,12),url:'https://yungprapz.github.io/habittracker/'}))" | ruby -ruri -e 'File.binwrite("bloom-reminders.ics", URI.decode_www_form_component(STDIN.read.strip))'`

## Product direction approved by user
Cream, sage/olive, butter yellow, muted rose. Botanical flower-shop theme, no smiling flowers. Quiet serif headings and readable body text. Pressed-flower journal look: paper cards with soft shadows, washi tape, wax seals, a forest-green streak card, a progress ring and a week strip on Today (style.css tokens on :root). Florist-tag buttons for primary actions. Navigation is a floating pill tab bar with line icons (Today, Flowers, Progress, Routines); Bouquet and Collection were merged into Flowers at the user’s request. Earn a flower per qualifying day, collect seven stems into a bouquet, retain finished bouquets on a shelf. Avoid crowded garden plots and generic pill-card UI.

Habit history must remain accurate after edits. Local dates, offline checkoffs and undo are required. Morning: thyroid medicine, Vitamin C SERUM, moisturizer, sunscreen. Night: red light mask, serum, moisturizer, retinol any 2 nights a week (a weekly habit, habit.perWeek; editable), hair oiling; then Vitamin D, iron and creatine as separate checkoffs. Reminder times 07:00/22:00 local time. The app day ends at state.dayEnd (default 4 am, 0–6, set under Evening routine) so late-night evening checkoffs count for the evening before; use model.js today() for the app's current day and localDate(d) only to format a given date. Routines → Reminders adds both routines as repeating calendar events with alerts: iOS blocks data:/blob: .ics in Home Screen apps, so default times link to the static bloom-reminders.ics (served as text/calendar) and other times to a service-worker-generated bloom-reminders.ics?m=&n=. state.reminders records the times last sent so the app can say when to re-add. No push notifications; Apple Reminders steps remain as a fallback.

Hair goal: 42 then 66 streak days under a "never miss twice" rule (one rest day pauses, two reset), separate from cumulative flower collection. Surprise treats unlock at 21, 42 and 66 days, scratch or accessible button to reveal, swap and claim. Fixed £10/£25 rewards were superseded: user wants variable surprises within chosen spending limits. The spending-limits UI was removed at the user's request, so treats are free unless a save already holds limits; never buy anything automatically.

## Files
- app.js: main views and persistence
- model.js: local dates, schedule versions, streaks
- garden.js: stem eligibility, collection, milestones, budget reservations, SVG art
- garden-ui.js: bouquet, collection and scratch UI
- reminders.js: calendar (.ics) reminders; sets globalThis.bloomReminders so sw.js can importScripts it
- bloom-reminders.ics: default-times calendar file generated from reminders.js
- sw.js: offline shell and the custom-time reminders route; bump cache on asset changes. Network-first with cache:'no-cache' (revalidates despite GitHub Pages' 10-minute max-age) and refreshes the offline copy of shell files; install fetches with cache:'reload' and calls skipWaiting; app.js registers it with updateViaCache:'none'

## Known limitations / next work
The implemented SVG flowers are simpler than the approved visual mockups. Custom reward categories, exclusions, wishlists, manually arranging individual stems, and editable daily flower goal are unfinished (each completed routine, morning and evening, earns one stem; optional habits are excluded). Surprise pool is curated local suggestions, not AI-generated or live shopping inventory. Budget caps reserve allowances in reveal month; review UX for cross-month claims. Reward milestones persist once earned; review explicit policy for historical corrections. Harden imported backup validation, including garden data, and recovery from corrupt localStorage before release. Deployed by GitHub Pages from main at https://yungprapz.github.io/habittracker/. Push is not configured. Physical iPhone testing is outstanding, including whether the calendar sheet opens from the Home Screen app and whether imported alerts fire.

## Validation
Twenty-three Node tests cover the late-night day cutoff, calendar reminders (format, line folding, midnight wrap, static file in sync), defaults, history, local dates/DST, never-miss-twice streaks, weekly habits, optional habits (and the one-time Vitamin D/creatine switch), automaticity scoring, save upgrades, morning/evening stems, rare and comeback blooms, milestones (21/42/66), budget reservations and serialization. Chromium checks were run at 320/390/768 widths, with offline reload, isolated demo data, collection, reveal, pointer scratching and persistence. Screenshots/video in demo are illustrative demo data, not real user history.

## Habit-science features (feat/habit-science)
Never-miss-twice streaks (model.js streakInfo), inline flower pick on Today plus evening flowers (garden-ui.js pickers, garden.js stemKey: evening stems are keyed `date:night`, morning stems keep the bare date), "After I…" routine anchors (state.anchors), 66-day milestone, optional habits (habit.light, shown as "Optional" inline in its routine, excluded via model.js active(); Vitamin D and creatine are optional by default and model.js optionalSupplements() switched existing saves once, guarded by state.optionalSupplements). The monthly automaticity check UI was removed at the user's request; model.js still exports its helpers and old state.auto data is kept. Weekly habits (habit.perWeek 1–6) show every day, are excluded from active() and measured Monday–Sunday (weekCount, weeksMet). Following a UI review (Clue-inspired, keep colours/theme): Today is checklist-first (slim ring header, no instruction copy, daily habits have no subtitle, a finished routine folds into a card holding its own flower picker via garden-ui.js pickerFor, unfinished routines first, one-line hair streak with the rule behind "?", no studio link); Progress is calendar plus a collapsible day summary; Flowers shows earned envelopes plus one next-treat timeline row; Routines groups habit editors by routine with anchor and time in the header, tap-to-edit rows, Up/Down reorder within a routine. Naming: "habits", "Morning routine", "Evening routine". Notices clear after ~3s. The Flowers tab no longer has wrapping, collect-for-date or spending-limit controls; collect for a past day by picking it in Today's week strip, and unannounced rare blooms (10% chance, always on a comeback day). README "Why it works this way" lists the research behind each.
